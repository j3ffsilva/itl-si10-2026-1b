def gerar_tempos_uniforme(objetivo, usou_busca, faixa_horaria):

    params_busca = {
        'buscar_sistema': (4.0, 0.55),
        'buscar_documento': (4.0, 0.55),
        'buscar_pessoa': (4.0, 0.55),
        'ler_comunicado': (2.9, 0.45),
        'acompanhar_noticias': (3.2, 0.50),
    }

    mu_b, sig_b = params_busca.get(objetivo, (3.5, 0.50))

    # Busca continua log-normal
    tempo_busca = np.random.lognormal(mu_b, sig_b)


    # ALTERAÇÃO PRINCIPAL


    if objetivo in {'ler_comunicado', 'acompanhar_noticias'}:
        tempo_leitura = np.random.uniform(80, 420)
    else:
        tempo_leitura = np.random.uniform(30, 180)

    # Ajustes comportamentais
    if not usou_busca:
           tempo_busca *= 0.45

    if faixa_horaria == '08-11':
        tempo_leitura *= 0.88
        tempo_busca *= 1.08

    ruido = np.random.gamma(shape=2.0, scale=8.0)

    tempo_total = tempo_busca + tempo_leitura + ruido

    return tempo_busca, tempo_leitura, tempo_total

### Documentação — Exercício 8.2

A substituição da distribuição log-normal por uma distribuição uniforme alterou significativamente o comportamento de `tempo_leitura_segundos`.

O principal impacto ocorreu no teste de aderência estatística. A distribuição uniforme remove a cauda direita típica de tempos reais de leitura, tornando os dados menos parecidos com padrões observados em comportamento humano. Assim, a fidelidade estatística da base piora.

Por outro lado, a coerência entre `tempo_leitura_segundos` e `clicou_comunicado` ainda permanece parcialmente preservada, pois usuários que clicam continuam apresentando tempos médios maiores.

Portanto, a nova base não é necessariamente “melhor” ou “pior” de forma absoluta. Ela melhora a regularidade dos dados, mas perde realismo estatístico. Isso demonstra que otimizar um eixo do scorecard pode degradar outro.
